# A prepared Milky Way sky for 0.7

**Recommendation, 19 November 2026.** Generate one seamless image from the system seed during stage preparation. The generator takes a continuous shape parameter with three art-directed anchors, Narrows, Practice and Broad reach. Pin the recipe and seed for Practice. Its identical output can be prepared during the build. Put it inside the flight stage, underneath World, and let the browser move it as a single picture. Dust, grain and distant stars can all share those pixels. The only sky work flight code needs during a coast is updating a transform when the camera centre moves.

Use 45% stream brightness and full-strength star marks as the initial recipe settings. Keep stream gain editable in the recipe. As the camera moves 100 world units, the bank travels 65 logical stage pixels in the opposite direction. It holds its apparent scale as the world camera widens. This is what lets the Sun and The Cradle recede while the galaxy still gives the eye somewhere to rest. The final Narrows still illustrates _another system_. The Practice targets are the middle still and the earlier moving bank crossing. ## Where the cost is today

All four modes already meet in `FlightDeck`. The first two shared passes fill World with the opaque void and visit the visible cells of a seeded star grid to draw points under the world camera. The grid is bounded at 4,096 candidate cells per call. World, screen-blended FX and hard-light LFX are canvases in an isolated CSS group. An image on the page behind that group would be covered by World. The title has its own clear and finite star list. [Flight frame](../../packages/mode-a/src/lib/flight-frame.ts) · [Starfield](../../packages/core/src/lib/entities/starfield.ts) · [Layer host](../../apps/web/src/components/FlightLayers.svelte) · [Flight deck](../../apps/web/src/components/FlightDeck.svelte)

The retired painter sampled a 1536² dust field, considered 145,000 grain candidates, and made separate 3072² stream and star patterns. Flight then filled the viewport with each pattern on every draw. At four bytes per pixel, the two full-size sources alone represent 72 MiB, before scratch buffers, pattern storage or compositor surfaces. The split let the designer adjust the stream independently. Baking that adjustment removes the need to keep a second star image in play. [Archived painter](https://github.com/villetakanen/void-drift/blob/fdc1772fbefef0394a386086ffd0f4eeb2f71b3d/docs/loop-evidence/2026-11-19-milky-way-sky-source/sky.ts.txt)

I ran the archived Practice recipe in three fresh pages of headless Chrome 157.0.8103.79 on an M4 Max MacBook Pro. Synchronous preparation took 247 ms in each run. I composited the plane at 45% over the game void, added the stars at full strength, and encoded one opaque PNG at each size. Decode times below start with a Blob already in memory.

| Baked tile | PNG bytes | RGBA pixel storage | Local decode |
| ---------- | --------: | -----------------: | -----------: |
| 1536²      |   445,780 |              9 MiB |         7 ms |
| 2048²      |   692,026 |             16 MiB |        10 ms |
| 3072²      | 1,273,583 |             36 MiB |        20 ms |

In a separate 1280 × 720, DPR 1 Chrome fixture, a repeating 1536² image sat under a transparent, actively drawn World canvas. I moved a 10° transformed sky element with a compositor hint. Chrome identified its layer and reported paint count **1 before and 1 after 120 moving frames**, after 35 warm-up frames. The layer’s reported dimensions were **2960 × 2640 CSS pixels**. This is both the feasibility result and the reason to size the plane carefully. The experiment measured browser paint reuse. Full-flight blend cost, texture upload, cold network load, iPad memory and downsampled star fidelity still need measurement. Browser guidance supports transform-based movement and parallel image decode. ## Production design

1. **Describe the sightline.** Mode A derives a versioned, presentation-only description from the final system seed. Give shape, dust detail and placement independent deterministic values so tuning one does not reshuffle the others or consume gameplay randomness. Start with a shape coordinate from 0 to 1. Use the study’s breadth / contrast / exposure triples as anchors: Narrows at 0 uses 0.76 / 1.35 / 1.00, Practice at 0.5 uses 1.00 / 1.00 / 1.00, and Broad reach at 1 uses 1.42 / 0.83 / 0.82. Interpolate the recipe parameters on each half. This lets the shoulders widen, the cuts soften and the bank grow dimmer together. A separate dust seed locates the crests and cuts, so two systems of equal breadth can still look different. Apply heading and overall scale to the completed sky about its bank. Practice always uses the midpoint, its fixed dust seed and its reference placement.
2. **Prepare one image.** Core owns the procedural recipe. At stage load, fill the tile with the void colour, evaluate dust and diffuse light within the galactic band at a lower resolution, then scale that field up and stamp seeded fine stars once onto the output. This puts detail where a pilot can see it and avoids sampling expensive noise across empty sky. Use periodic coordinates so both tile edges join. Compare 1536² and 2048² output at the same 3072-logical-pixel repeat period against the Practice reference. For generated systems, prototype a worker that returns one image Blob for the shared repeating CSS surface. Measure worker startup, generation, encoding, main-thread decode, first visible frame and peak memory together. Keep a bounded working set and release scratch storage after preparation. Practice can ship the frozen output of the same recipe once it matches the reference.
3. **Present once per stage.** Extend the shared layer host with a clipped, decorative, pointer-transparent sky plane inside its isolated group, with the opaque void as its base. Keep World as the sizing and accessible canvas. In the prepared-sky flight path, replace the opaque World clear with a full transparent clear in backing coordinates and omit the stock star pass. Clear World every frame so moving ships leave no ghost. Keep FX, LFX, the Deck, and their drawing order above it. Describe Sky in the render model as a prepared image surface. Adding it to the canvas context registry would incorrectly allocate a fourth game canvas.
4. **Move the picture.** Set the repeating background image, tile size, pivot, system heading and scale at bind time. Use the absolute camera centre and system anchor to compute pan, so a wrap snaps on the same frame as the world, and pause, restart and backwards seek need no sky history. Anchor the bank relative to stage centre, calibrated against the 16:10 Practice capture. Convert logical pixels to displayed pixels with the stage’s fitted scale once. Recalculate coverage on resize. Pass the camera pose from the existing frame clock and skip identical transforms. Avoid changing CSS background position or size in the frame loop.
5. **Bound coverage and lifetime.** Inverse-transform the four stage corners into tile coordinates to size a repeating plane for the viewport at the chosen heading and scale. Reduce the pan in that same rotated tile space by whole periods and allow one period of travel on each axis. This keeps the plane finite, including at steep angles and ultra-wide widths. Inspect the actual composited surface on iPad. If overscan is costly, compare a viewport-sized grid of instances sharing the decoded tile, sized to the rotated corner bounds plus the edge tiles. Keep the same camera mapping. Prepare only the current sightline. Cancel superseded generation, bind the finished image only if its run is still current, and release its object URL and any pending worker resources on replacement or unmount.

Bind after `reset(true)` has selected the real run seed. Start loading fixed Practice art as soon as that route is known. Generated modes can use their arrival transition to overlap preparation. For a late or failed image, the opaque stage void gives a complete flight surface immediately. Input, countdown, simulation ticks and ranked scoring continue on their existing clocks. Stage resize, pause and replay seek reuse the bound image. The sky needs no new Firebase field, replay input, simulation RNG draw or animation loop.
