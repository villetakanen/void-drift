# The plans

This folder is the project's ongoing conversation: plans, briefs, prompts and
notes we leave for each other and for the next session. Read it as the team's
current thinking, the zeitgeist, not as decisions.

What's here was true when it was written and goes stale from then on. Check
the date, then check the specs (intent) and the code (what is actually built)
before acting on anything.

Some habits that help:

- Dated names, `2026-11-10-topic.md`, so it is easy to see how old a thought is.
- A brief when handing work to another session: what to do, why, what we
  know, and what worked or didn't.
- When something here is decided, say so with a date, and move it into a spec
  once it holds.

Plans, not decisions.
