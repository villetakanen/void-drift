# Guidance extraction: context, delegation and learning

Read from direct public-page captures on 12 November 2026. URLs, page dates, maturity and content hashes are in [the capture manifest](guidance-capture.json). Anchors below name actual page headings. These are propositions for comparison, not requirements that every project adopt every pattern. The listed pages were read; supporting studies cited by those pages were not independently evaluated.

| ID    | Guidance and status                                                                                                                                                                  | Proposition and caveat                                                                                                                                                                                                                                                                              |
| ----- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| G-C01 | [Compound Loop](https://asdlc.io/patterns/compound-loop/), Live; Definition, The Solution, Anatomy and Structure                                                                     | Candidate learning crosses human review before becoming scoped, reusable context. Retrieval is on demand. The page already warns against automatic writeback and undifferentiated accumulation; a proposal must extend this existing discrimination, not claim it is absent.                        |
| G-C02 | [Compound Engineering](https://asdlc.io/concepts/compound-engineering/), Live; Key Characteristics, Open Questions                                                                   | Describes the named industry's practice and distinguishes it from ASDLC's governed pattern. It explicitly questions universal time ratios, productivity multipliers and missing provenance. This case cannot establish those quantitative claims.                                                   |
| G-C03 | [Agent Optimization Loop](https://asdlc.io/patterns/agent-optimization-loop/), Experimental; Anatomy, Offline vs Online Evolution, Controlled Evaluator Evolution                    | Agent configuration is evaluated against scenarios; governed validation separates proposals from promotion. Later sections discuss held-out tasks and frozen evaluators. The early failure-to-prompt/context/tool diagnosis is a simplification; it must be read with those validation constraints. |
| G-C04 | [Model Routing](https://asdlc.io/patterns/model-routing/), Live; The Iron Triangle, Anatomy, Trade-offs                                                                              | Select capability against quality, cost and latency; calibrate decisions rather than assume model labels establish value. Routing itself has overhead and can produce inconsistency. Manual role assignment is evidence of task allocation, not a measured routing optimum.                         |
| G-C05 | [External Attention](https://asdlc.io/patterns/external-attention/), Draft; Anatomy, When Not to Use                                                                                 | Isolated readers return bounded answers. The pattern excludes tasks needing holistic understanding or unclear queries. It does not establish that extracted answers are faithful; coordinator synthesis and source checks remain distinct work.                                                     |
| G-C06 | [Context Map](https://asdlc.io/patterns/context-map/), Experimental; The Solution, Anatomy                                                                                           | Separate a compact navigation map from detailed knowledge. It explicitly distinguishes this retrieval map from DDD subsystem relationships. A map identifies sources; it does not establish retrieval or obedience during an episode.                                                               |
| G-C07 | [Context Offloading](https://asdlc.io/practices/context-offloading/), Experimental; Process, Common Mistakes                                                                         | Move bulky trajectories/results to files and preserve raw material before replacing it with summaries. This is temporary working-state management; durable evidence retention has a different purpose and lifespan.                                                                                 |
| G-C08 | [Agent Skills](https://asdlc.io/concepts/agent-skills/), Live; Progressive Disclosure, Horizontal vs. Vertical Context                                                               | Separate global orientation from task-specific procedures. The page already discusses limited or negative gains from poorly matched skills. Having more skills is therefore not a success measure under the guidance.                                                                               |
| G-C09 | [Ralph Loop](https://asdlc.io/patterns/ralph-loop/), Live; Definition, Anatomy, Anti-Patterns                                                                                        | Persistence uses external verification, bounded scope, iteration caps and retained state. It explicitly says persistence does not establish quality. Open design inquiry without a settled observable finish line is not automatically an instance of this pattern.                                 |
| G-C10 | [Micro-Commits](https://asdlc.io/practices/micro-commits/), Live; 4.3 Branches and Worktrees for Isolation, 4.4 Rollback, 5. The Merge Boundary                                      | Small save points support attribution and rollback; the page already recommends isolated worktrees and recognises squash trade-offs. A shared-tree commit containing unrelated changes does not acquire task isolation merely by having a hash.                                                     |
| G-C11 | [Context Engineering](https://asdlc.io/concepts/context-engineering/), Live; Key Characteristics, Organizational Context Through Platform Interfaces, Toolchain as Context Reduction | Context is versioned, structured and task-relevant. Enforce mechanically checkable constraints in tooling. The page distinguishes context availability from verification capacity and says a platform example is not a universal requirement.                                                       |
| G-C12 | [Legend](https://asdlc.io/resources/legend/) and [Content Governance](https://asdlc.io/resources/governance/); Status Definitions, Frontmatter Schema                                | Status is part of how readers interpret guidance; content governance identifies status/update metadata and deprecation relationships. Live, Experimental, Draft and Proposed material should not silently become one undifferentiated checklist.                                                    |

The assessment reads these sources as framework claims. It does not independently validate their third-party studies, model economics, autonomy safety claims or mathematical convergence model.
