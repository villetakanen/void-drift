## Current gate and authority model

**E-G01 — Declared flow and determinism.** `docs/specs/factory/spec.md:33-35,47-61` defines the sequence as spoken intent → concise contract → bounded implementation → deterministic gates → browser/Lab evidence → human experience review → local commit → explicitly authorized publication. It describes test adapters fixing time, randomness, input and network outcomes and separates live services from deterministic checks. The definition of done requires named pass/fail results, explicit skipped/unavailable checks, revision/dirty state/commands/environment, and invalidation after source edits (`spec.md:49-66`). This is documented intent, not evidence that every conversation follows the path.

**E-G02 — Executable full and quick verification.** At baseline, `package.json:10-23` maps `verify` and `verify:quick` to `scripts/verify.mjs`; the runner names nine stages (`verify.mjs:22-36`): contracts (including factory runner fixtures), commit syntax, lint, types, unit tests, build, browser, rules and competition. Full runs execute sequentially; backend rules/competition share an owned emulator lifecycle (`verify.mjs:95-128`; `verify-backend.mjs`, `docs/development.md:45-53`). The runner records a unique per-invocation report/log directory; it captures revision, branch, status, source fingerprint, runtime and browser URLs (`verify.mjs:45-90`), then fingerprints again. Any failed step, backend lifecycle failure or changed source prevents success (`verify.mjs:130-146`). Commands are not auto-fixing.

Quick selects only contracts, lint, types and unit tests (`verify.mjs:33-36`); it records omitted steps and `partial: true`, sets `passed` only for full mode (`verify.mjs:77-90,130-146`). Thus exit zero/`selectedChecksPassed: true` is not a full pass. The factory contract also states command errors/signals fail even with child exit zero, and the browser suite has a ten-minute deadline (`spec.md:70-78`). Local artifacts are useful provenance but ignored and non-durable; `latest.json` is a convenience pointer, not historical identity (`development.md:75-82`, `spec.md:63-66`).

**E-G03 — Review and retained authority.** Automated checks cover bounded claims, not overall correctness, aesthetic merit, balance or physical-device performance. Browser correctness/capture and human judgment are distinct (`development.md:84-109`; `spec.md:102-120,174-180`). Capture is opt-in for review; capture completion is not human approval. `AGENTS.md` calls for inspectable playable evidence; it does not make human playtesting a gate. Release preparation is only allowed after full verification on a stable candidate, while human review remains separate evidence (`development.md:147-166`; `spec.md:143-146`). Local commit, push, deployment and verified live behavior are separate states; release/push/publication require explicit authority (`development.md:174-192`; `spec.md:148-152`).

**E-G04 — Release chain.** `release:prepare` validates production Firebase configuration, snapshots rules/indexes/config, builds once, verifies identifiers in JS, and smoke-tests the built output offline. It records revision, dirty state, source/artifact hashes and smoke outcome. Source mutation, failed build/smoke or bundle mutation cannot yield a prepared artifact (`scripts/release.mjs:96-196`; `release:check` validates full file hashes at `:198-213`). Preparation/check do not publish. After authorization, `release:publish` validates and deploys a hash-checked copy of that exact bundle, with attempt-specific outcome, and does not rebuild or consume current checkout inputs (`:215-255`). Deployment report deliberately retains `liveVerified: false`; separate live checks are required (`development.md:174-192`; `spec.md:148-156`).

**E-G05 — CI changed over time.** Historical alpha retrospective records a hosted CI workflow uploading artifacts even after failures, independent Linux/macOS runs and one successful Actions run in late October (`docs/factory-experiment-alpha.md:80-85,99-103,114-134`). Current development and factory specification say hosted CI was removed 2026-11-08 and retained local reports are now verification evidence (`docs/development.md:69-82`; `docs/specs/factory/spec.md:122-126`). This packet confirms the current repository documentation and runner arrangement, but does not inspect hosted service configuration/history to establish why CI was removed or whether a remote system still exists.

## Bounded interpretation for synthesis

The evidence shows a layered gate design: executable deterministic checks and report provenance establish outcomes only for an identified candidate; quick is structurally partial; offline production smoke validates a built artifact; publish consumes the checked snapshot; live service checks are separate; human experience judgment remains a distinct authority. Retained incidents show the distinction has practical consequences: stale fixtures, port restrictions, shared-tree edits and runner timeout handling all changed whether evidence was usable, and failed attempts were retained rather than relabeled as passes.

Rationale is explicit for some local choices (warn-to-fail after relocation; quick runner isolation; release authorization and score-comparability rules), but this packet does not establish why hosted CI was removed, effectiveness of the gate set across all changes, or a causal relation to ASDLC.io guidance. Current evidence is documentation, runner code, local ignored reports and tracked closures; no fresh checks or human gameplay review were performed. Historical records span different versions and do not imply today's nine-stage implementation was present throughout.
